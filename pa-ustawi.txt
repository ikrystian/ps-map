## USTAWIENIA SYSTEMOWE
**Ścieżka:** `/admin/settings`
**Dostęp:** Wyłącznie administratorzy (rola ADMIN)
**Plik:** `/prosta-sprawa/app/admin/settings/page.tsx`

### OPIS OGÓLNY
Panel ustawień systemowych umożliwia administratorom konfigurację globalnych parametrów platformy Prosta Sprawa. Wszystkie ustawienia są przechowywane w bazie danych w modelu `Settings` w formacie klucz-wartość z opcjonalnym opisem.

### FUNKCJONALNOŚCI

#### 1. USTAWIENIA OGÓLNE

**Nazwa serwisu (siteName)**
- **Typ:** Pole tekstowe
- **Domyślna wartość:** "Prosta Sprawa"
- **Zastosowanie:** Nazwa wyświetlana w:
  - Nagłówku strony (header)
  - Meta tagach SEO (title, og:title)
  - Emailach systemowych
  - Stopce (footer)
- **Walidacja:** Brak walidacji (może być puste)
- **Pole w bazie:** `key: "siteName"`, `value: "<nazwa>"`

**Email kontaktowy (contactEmail)**
- **Typ:** Pole email
- **Domyślna wartość:** "kontakt@prostasprawa.pl"
- **Zastosowanie:**
  - Główny adres kontaktowy wyświetlany na stronie
  - Używany w formularzach kontaktowych
  - Pokazywany w stopce strony
- **Walidacja:**
  - Wymagane pole (nie może być puste)
  - Walidacja formatu email (podstawowa)
- **Pole w bazie:** `key: "contactEmail"`, `value: "<email>"`

**Email wsparcia (supportEmail)**
- **Typ:** Pole email
- **Domyślna wartość:** "pomoc@prostasprawa.pl"
- **Zastosowanie:**
  - Email wsparcia technicznego
  - Adres do zgłoszeń problemów
  - Pokazywany w sekcji pomocy
- **Walidacja:**
  - Wymagane pole (nie może być puste)
  - Walidacja formatu email
- **Pole w bazie:** `key: "supportEmail"`, `value: "<email>"`

#### 2. USTAWIENIA KANCELARII

**Maksymalna liczba kategorii dla kancelarii (maxLawFirmCategories)**
- **Typ:** Pole numeryczne (input type="number")
- **Domyślna wartość:** 10
- **Zakres wartości:** 1-100
- **Zastosowanie:**
  - Określa limit kategorii prawnych, które kancelaria może wybrać
  - Kontroluje w formularzu edycji profilu kancelarii
  - Zapobiega nadmiernemu rozproszeniu oferty kancelarii
- **Walidacja:**
  - Musi być liczbą całkowitą
  - Zakres: minimum 1, maksimum 100
  - Komunikat błędu: "Maksymalna liczba kategorii musi być liczbą od 1 do 100"
- **Pole w bazie:** `key: "maxLawFirmCategories"`, `value: "10"`
- **Opis w bazie:** "Maksymalna liczba kategorii, które może zaznaczyć kancelaria"

#### 3. USTAWIENIA OPINII

**Liczba opinii na stronę (reviewsPerPage)**
- **Typ:** Pole numeryczne
- **Domyślna wartość:** 10
- **Zakres wartości:** 5-50
- **Zastosowanie:**
  - Kontroluje paginację opinii na:
    - Profilach kancelarii
    - Liście opinii w panelu administracyjnym
    - Sekcji opinii klientów
- **Walidacja:**
  - Musi być liczbą całkowitą
  - Zakres: minimum 5, maksimum 50
  - Komunikat błędu: "Liczba opinii na stronę musi być liczbą od 5 do 50"
- **Pole w bazie:** `key: "reviewsPerPage"`, `value: "10"`
- **Opis w bazie:** "Liczba opinii wyświetlanych na jednej stronie"

**Minimalna długość opinii (minReviewLength)**
- **Typ:** Pole numeryczne
- **Domyślna wartość:** 50
- **Zakres wartości:** 10-500 znaków
- **Zastosowanie:**
  - Walidacja formularza dodawania opinii
  - Zapewnia, że opinie są merytoryczne i szczegółowe
  - Zapobiega spamowi i beztreściowym opiniom
- **Walidacja:**
  - Musi być liczbą całkowitą
  - Zakres: minimum 10, maksimum 500
  - Komunikat błędu: "Minimalna długość opinii musi być liczbą od 10 do 500"
- **Pole w bazie:** `key: "minReviewLength"`, `value: "50"`
- **Opis w bazie:** "Minimalna liczba znaków w opinii"

#### 4. USTAWIENIA WYŚWIETLANIA

**Limit wyróżnionych kategorii (featuredCategoriesLimit)**
- **Typ:** Pole numeryczne
- **Domyślna wartość:** 8
- **Zakres wartości:** 4-20
- **Zastosowanie:**
  - Określa liczbę kategorii wyświetlanych na stronie głównej
  - Kontroluje sekcję "Popularne kategorie"
  - Wpływa na UX i czytelność strony głównej
- **Walidacja:**
  - Musi być liczbą całkowitą
  - Zakres: minimum 4, maksimum 20
  - Komunikat błędu: "Limit wyróżnionych kategorii musi być liczbą od 4 do 20"
- **Pole w bazie:** `key: "featuredCategoriesLimit"`, `value: "8"`
- **Opis w bazie:** "Maksymalna liczba wyróżnionych kategorii na stronie głównej"

### STANY APLIKACJI

**Stan ładowania (loading):**
- Wyświetlany przy pierwszym załadowaniu strony
- Pokazuje animowany spinner (Loader2) na środku ekranu
- Komunikat: brak (tylko spinner)

**Stan zapisywania (saving):**
- Aktywowany po kliknięciu przycisku "Zapisz"
- Przycisk jest wyłączony
- Wyświetla animację ładowania
- Blokuje możliwość ponownego zapisu

**Stan sukcesu:**
- Toast notification: "Ustawienia zostały zapisane" (zielony)
- Automatyczne odświeżenie danych z serwera (fetchSettings())

**Stan błędu:**
- Toast notification z komunikatem błędu (czerwony)
- Możliwe komunikaty:
  - "Nie udało się pobrać ustawień" (przy ładowaniu)
  - "Nie udało się zapisać ustawień" (przy zapisie)
  - Szczegółowe błędy walidacji (dla każdego pola)

## LOGI SYSTEMOWE
**Ścieżka:** `/admin/logs`
**Dostęp:** Wyłącznie administratorzy (rola ADMIN)
**Plik:** `/prosta-sprawa/app/admin/logs/page.tsx`

### OPIS OGÓLNY
System logowania śledzi wszystkie istotne zdarzenia i akcje wykonywane w platformie Prosta Sprawa. Panel logów umożliwia administratorom przeglądanie, filtrowanie i analizę logów systemowych w celu monitorowania aktywności, debugowania problemów i audytu bezpieczeństwa.

### POZIOMY LOGOWANIA (LogLevel)

System obsługuje 5 poziomów logowania, zgodnie z enum LogLevel:

1. **DEBUG** 🐛
   - **Kolor:** Szary (bg-gray-500)
   - **Ikona:** Bug
   - **Zastosowanie:** Szczegółowe informacje diagnostyczne
   - **Przykłady:**
     - Szczegóły zapytań do bazy danych
     - Wartości zmiennych w trakcie wykonywania
     - Debugowanie złożonych operacji

2. **INFO** ℹ️
   - **Kolor:** Niebieski (bg-blue-500)
   - **Ikona:** Info
   - **Zastosowanie:** Informacje o normalnym działaniu systemu
   - **Przykłady:**
     - Logowanie użytkownika
     - Utworzenie nowej sprawy
     - Zmiana statusu zamówienia

3. **WARNING** ⚠️
   - **Kolor:** Żółty (bg-yellow-500)
   - **Ikona:** AlertTriangle
   - **Zastosowanie:** Ostrzeżenia, które nie są błędami
   - **Przykłady:**
     - Zbliżanie się do limitu zasobów
     - Przestarzałe API
     - Nieprawidłowe dane wejściowe (niekrityyczne)

4. **ERROR** ❌
   - **Kolor:** Pomarańczowy (bg-orange-500)
   - **Ikona:** XCircle
   - **Zastosowanie:** Błędy, które nie zatrzymują działania systemu
   - **Przykłady:**
     - Nieudane połączenie z zewnętrznym API
     - Błąd walidacji formularza
     - Niepowodzenie wysyłki emaila

5. **CRITICAL** 🔴
   - **Kolor:** Czerwony (bg-red-500)
   - **Ikona:** AlertCircle
   - **Zastosowanie:** Krytyczne błędy wymagające natychmiastowej uwagi
   - **Przykłady:**
     - Utrata połączenia z bazą danych
     - Błędy bezpieczeństwa
     - Awaria płatności

### FUNKCJONALNOŚCI

#### 1. FILTROWANIE LOGÓW

**Filtr poziomu logu (levelFilter):**
- **Typ:** Select dropdown
- **Opcje:**
  - "Wszystkie" (all) - domyślne
  - "Debug" (DEBUG)
  - "Info" (INFO)
  - "Ostrzeżenie" (WARNING)
  - "Błąd" (ERROR)
  - "Krytyczny" (CRITICAL)
- **Działanie:**
  - Zmiana wartości automatycznie filtruje logi
  - Resetuje paginację do strony 1
  - Wywołuje ponowne pobranie danych z API

**Wyszukiwanie tekstowe (searchFilter):**
- **Typ:** Input tekstowy + przycisk "Szukaj"
- **Placeholder:** "Szukaj w wiadomościach i akcjach..."
- **Działanie:**
  - Wyszukuje w dwóch polach:
    - `message` - wiadomość logu
    - `action` - typ akcji
  - Obsługa Enter - uruchomienie wyszukiwania
  - Przycisk "Szukaj" z ikoną Search
  - Resetuje paginację do strony 1

#### 2. STATYSTYKI LOGÓW

Panel statystyk wyświetla 6 kart (Cards):

**Karta "Wszystkie":**
- Wyświetla całkowitą liczbę logów
- Ikona: FileText (szara)
- Dane z pola `pagination.total`

**Karty poziomów logowania (5 kart):**
- Każda karta reprezentuje jeden poziom (DEBUG, INFO, WARNING, ERROR, CRITICAL)
- Wyświetla odpowiednią ikonę z opacity 50%
- Wartość: "-" (obecnie nieimplementowane - wymaga dodania zliczania)
- **Interaktywność:**
  - Kliknięcie karty ustawia filtr na dany poziom
  - Cursor: pointer
  - Hover: bg-muted/50

#### 3. TABELA LOGÓW

**Kolumny tabeli:**

1. **Data (createdAt)**
   - Szerokość: 120px
   - Format: "dd.MM.yyyy HH:mm:ss" (polski format)
   - Biblioteka: date-fns
   - Przykład: "15.11.2025 14:23:45"

2. **Poziom (level)**
   - Szerokość: 100px
   - Wyświetlenie: Badge z odpowiednim kolorem
   - Zawiera ikonę + nazwę poziomu
   - Kolory zgodne z levelColors

3. **Akcja (action)**
   - Szerokość: 200px
   - Font: monospace (font-mono)
   - Rozmiar: text-xs
   - Przykłady wartości:
     - "USER_LOGIN"
     - "ORDER_CREATED"
     - "PAYMENT_STATUS_CHANGED"

4. **Wiadomość (message)**
   - Szerokość: elastyczna
   - Wyświetlenie: Tekst z truncate (skrócony)
   - Maksymalna szerokość: 400px (max-w-md)
   - **Metadane (metadata):**
     - Jeśli log posiada metadata, wyświetla element `<details>`
     - Summary: "Pokaż metadane" (text-xs text-muted-foreground)
     - Zawartość: Sparsowany JSON w czytelnym formacie
     - Style: pre-formatted z tłem (bg-muted), zaokrąglony, scrollable

5. **User ID (userId)**
   - Szerokość: 120px
   - Font: monospace (font-mono)
   - Wyświetlenie:
     - Jeśli istnieje: pierwsze 8 znaków + "..." z title zawierającym pełne ID
     - Jeśli null: "-" (text-muted-foreground)
   - Przykład: "a1b2c3d4..." (title: "a1b2c3d4-5e6f-7g8h-9i0j-k1l2m3n4o5p6")

6. **IP (ipAddress)**
   - Szerokość: 150px
   - Wyświetlenie adresu IP użytkownika
   - Jeśli null: "-"
   - Przykład: "192.168.1.1", "2001:0db8:85a3::8a2e:0370:7334"

**Formatowanie wierszy:**
- Hover: bg-muted/50
- Kursor: domyślny
- Wysokość: automatyczna (dopasowana do zawartości)

#### 4. PAGINACJA

**Mechanizm:**
- Limit na stronę: 50 logów (pagination.limit)
- Aktywna strona: pagination.page
- Całkowita liczba stron: pagination.totalPages

**Interfejs:**
- Lokalizacja: Pod tabelą
- Wyświetlenie: Tylko gdy totalPages > 1

**Elementy:**
1. Informacja tekstowa: "Strona X z Y"
2. Przycisk "Poprzednia":
   - Ikona: ChevronLeft
   - Disabled gdy page === 1
   - onClick: handlePageChange(page - 1)
3. Przycisk "Następna":
   - Ikona: ChevronRight
   - Disabled gdy page === totalPages
   - onClick: handlePageChange(page + 1)

### INTERFEJS UŻYTKOWNIKA

**Nagłówek strony:**
- Ikona: FileText
- Tytuł: "Logi Systemowe"
- Opis: "Przeglądaj i filtruj logi aktywności systemu"

**Sekcja filtrów (Card):**
- Tytuł: "Filtry" z ikoną Filter
- Layout: Grid 1 kolumna (mobile) / 3 kolumny (desktop)
- Zawiera:
  - Select poziomu (1 kolumna)
  - Input wyszukiwania + przycisk (2 kolumny)

**Sekcja statystyk:**
- Grid: 1 kolumna (mobile) / 5 kolumn (desktop)
- 6 kart statystycznych

**Sekcja tabeli (Card):**
- Tytuł: "Logi (X)" gdzie X = pagination.total
- Zawartość: Tabela lub stan pusty/ładowanie

```javascript
const parseMetadata = (metadata: string | null) => {
  if (!metadata) return null
  try {
    return JSON.parse(metadata)
  } catch {
    return null
  }
}
```

## MODELE BAZY DANYCH

### MODEL SETTINGS

**Lokalizacja:** `/prosta-sprawa/prisma/schema.prisma` (linie 1590-1599)

```prisma
model Settings {
  id                        String   @id @default(uuid())
  key                       String   @unique
  value                     String
  description               String?
  createdAt                 DateTime @default(now())
  updatedAt                 DateTime @updatedAt

  @@index([key])
}
```

**Pola:**

1. **id** (String, UUID)
   - Klucz główny
   - Automatycznie generowany (uuid())
   - Unikalne ID ustawienia

2. **key** (String, UNIQUE)
   - Klucz ustawienia
   - Unikalna wartość
   - Indeksowany dla szybkiego wyszukiwania
   - Przykłady: "siteName", "maxLawFirmCategories"

3. **value** (String)
   - Wartość ustawienia
   - Przechowywana jako string (nawet liczby)
   - Wymagane pole

4. **description** (String, nullable)
   - Opcjonalny opis ustawienia
   - Pomaga administratorom zrozumieć zastosowanie
   - Może być null

5. **createdAt** (DateTime)
   - Data utworzenia ustawienia
   - Automatycznie ustawiana (@default(now()))

6. **updatedAt** (DateTime)
   - Data ostatniej aktualizacji
   - Automatycznie aktualizowana (@updatedAt)

**Indeksy:**
- `@@index([key])` - Indeks na kolumnie key dla szybkiego wyszukiwania

**Przykładowe rekordy:**
```
id: "a1b2c3d4-..."
key: "siteName"
value: "Prosta Sprawa"
```

### MODEL SYSTEMLOG

**Lokalizacja:** `/prosta-sprawa/prisma/schema.prisma` (linie 1626-1641)

```prisma
model SystemLog {
  id          String      @id @default(uuid())
  level       LogLevel    @default(INFO)
  action      String      // Rodzaj akcji (np. "USER_LOGIN", "ORDER_CREATED")
  message     String      // Opis zdarzenia
  userId      String?     // ID użytkownika, który wykonał akcję (opcjonalne)
  metadata    String?     // Dodatkowe dane w formacie JSON
  ipAddress   String?     // Adres IP użytkownika
  userAgent   String?     // User agent przeglądarki
  createdAt   DateTime    @default(now())

  @@index([level])
  @@index([action])
  @@index([userId])
  @@index([createdAt])
}
```

**Pola:**

1. **id** (String, UUID)
   - Klucz główny
   - Automatycznie generowany
   - Unikalne ID logu

2. **level** (LogLevel enum)
   - Poziom logowania
   - Domyślnie: INFO
   - Wartości: DEBUG, INFO, WARNING, ERROR, CRITICAL
   - Indeksowany

3. **action** (String)
   - Rodzaj akcji/zdarzenia
   - Konwencja nazewnictwa: UPPER_SNAKE_CASE
   - Przykłady:
     - "USER_LOGIN"
     - "USER_LOGOUT"
     - "CASE_CREATED"
     - "OFFER_SUBMITTED"
     - "ORDER_CREATED"
     - "PAYMENT_STATUS_CHANGED"
     - "LAW_FIRM_VERIFIED"
   - Indeksowany dla szybkiego filtrowania

4. **message** (String)
   - Opis zdarzenia w języku naturalnym
   - Może zawierać szczegóły akcji
   - Przykłady:
     - "Użytkownik zalogował się do systemu"
     - "Utworzono nową sprawę: Rozwód z orzekaniem"
     - "Kancelaria wysłała ofertę na sprawę #123"

5. **userId** (String, nullable)
   - ID użytkownika, który wykonał akcję
   - Opcjonalne (null dla zdarzeń systemowych)
   - Indeksowany

6. **metadata** (String, nullable)
   - Dodatkowe dane w formacie JSON
   - Przechowuje kontekst akcji
   - Parsowane przy wyświetlaniu
   - Przykłady:
     ```json
     {
       "caseId": "uuid",
       "offerId": "uuid",
       "amount": 1500,
       "points": 100
     }
     ```

7. **ipAddress** (String, nullable)
   - Adres IP użytkownika
   - Opcjonalne
   - Obsługuje IPv4 i IPv6
   - Używane do audytu bezpieczeństwa

8. **userAgent** (String, nullable)
   - User agent przeglądarki
   - Opcjonalne
   - Pomaga identyfikować używaną przeglądarkę/urządzenie
   - Przykład: "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36..."

9. **createdAt** (DateTime)
   - Data i czas utworzenia logu
   - Automatycznie ustawiana
   - Indeksowana (sortowanie chronologiczne)

**Indeksy:**
- `@@index([level])` - Filtrowanie po poziomie
- `@@index([action])` - Filtrowanie po akcji
- `@@index([userId])` - Wyszukiwanie logów użytkownika
- `@@index([createdAt])` - Sortowanie chronologiczne

```typescript
for (const [key, data] of Object.entries(settings)) {
  const { value, description } = data as { value: string; description?: string }

  await prisma.settings.upsert({
    where: { key },              // Szukaj po kluczu
    update: {                    // Jeśli istnieje - aktualizuj
      value,
      description: description || null,
    },
    create: {                    // Jeśli nie istnieje - utwórz
      key,
      value,
      description: description || null,
    },
  })
}
```

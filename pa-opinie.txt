================================================================================
1. PRZEGLĄD SYSTEMU OPINII
================================================================================

System opinii w Prosta Sprawa umożliwia klientom wystawianie szczegółowych
recenzji kancelarii prawnych po zakończonej współpracy. Administrator może
zarządzać wszystkimi opiniami w systemie poprzez dedykowany panel
administracyjny.

KLUCZOWE MOŻLIWOŚCI:
- Przeglądanie wszystkich opinii z zaawansowanymi filtrami
- Moderacja opinii (weryfikacja, aktywacja/dezaktywacja)
- Edycja pełnej treści opinii
- Zarządzanie odpowiedziami kancelarii
- Usuwanie nieprawidłowych opinii
- System ocen wielokryterialnych (ogólna + 4 dodatkowe)

DOSTĘP:
- Wymagana rola: ADMIN
- Autoryzacja przez NextAuth.js (sesja JWT)
- Brak dostępu dla klientów i kancelarii prawnych

B) SYSTEM FILTROWANIA

Sekcja filtrów znajduje się w dedykowanej karcie nad tabelą opinii:

┌─────────────────────────────────────────────────────────────────────┐
│ FILTR           │ OPIS                          │ WARTOŚCI          │
├─────────────────────────────────────────────────────────────────────┤
│ Szukaj w treści │ Wyszukiwanie pełnotekstowe    │ Dowolny tekst     │
│                 │ Przeszukuje:                  │                   │
│                 │ - Tytuł opinii (tytulOpinii)  │                   │
│                 │ - Treść opinii (trescOpinii)  │                   │
│                 │ Tryb: case-insensitive        │                   │
├─────────────────────────────────────────────────────────────────────┤
│ Ocena           │ Filtrowanie po ocenie ogólnej │ - Wszystkie oceny │
│                 │                               │ - 5 gwiazdek      │
│                 │                               │ - 4 gwiazdki      │
│                 │                               │ - 3 gwiazdki      │
│                 │                               │ - 2 gwiazdki      │
│                 │                               │ - 1 gwiazdka      │
├─────────────────────────────────────────────────────────────────────┤
│ Weryfikacja     │ Filtrowanie po statusie       │ - Wszystkie       │
│                 │ weryfikacji                   │ - Zweryfikowane   │
│                 │                               │ - Niezweryfikowane│
├─────────────────────────────────────────────────────────────────────┤
│ Status          │ Filtrowanie po aktywności     │ - Wszystkie       │
│                 │                               │ - Aktywne         │
│                 │                               │ - Nieaktywne      │
└─────────────────────────────────────────────────────────────────────┘

MECHANIZM FILTROWANIA:
- Filtry działają w czasie rzeczywistym (useEffect z dependency array)
- Każda zmiana filtru resetuje paginację do strony 1
- Filtry są łączone logicznie (AND)
- Wyszukiwanie tekstowe używa operatora OR (tytuł LUB treść)


C) AKCJE NA LIŚCIE

Każda opinia ma 4 przyciski akcji:

1. ZOBACZ SZCZEGÓŁY (ikona: Eye)
   - Przekierowanie do /admin/reviews/[id]
   - Zawsze dostępny
   - Tooltip: "Zobacz szczegóły"

2. PRZEŁĄCZ WERYFIKACJĘ (ikona: CheckCircle)
   - Przełącza pole "zweryfikowana" (true ↔ false)
   - API: PATCH /api/admin/reviews/[id]/status
   - Kolory:
     * Zielony (#green-600): opinia zweryfikowana
     * Szary (#gray-400): opinia niezweryfikowana
   - Tooltip:
     * "Zweryfikuj" (gdy niezweryfikowana)
     * "Oznacz jako niezweryfikowaną" (gdy zweryfikowana)
   - Toast po sukcesie:
     * "Opinia została zweryfikowana"
     * "Opinia została oznaczona jako niezweryfikowana"

3. PRZEŁĄCZ AKTYWNOŚĆ (ikona: CheckCircle / XCircle)
   - Przełącza pole "aktywna" (true ↔ false)
   - API: PATCH /api/admin/reviews/[id]/status
   - Ikony:
     * XCircle (pomarańczowy #orange-600): gdy aktywna
     * CheckCircle (szary #gray-400): gdy nieaktywna
   - Tooltip:
     * "Dezaktywuj" (gdy aktywna)
     * "Aktywuj" (gdy nieaktywna)
   - Toast po sukcesie:
     * "Opinia została aktywowana"
     * "Opinia została dezaktywowana"

4. USUŃ (ikona: Trash2)
   - Otwiera dialog potwierdzenia
   - Kolor: destructive (czerwony)
   - Tooltip: "Usuń"

F) STANY INTERFEJSU

1. LOADING (początkowe ładowanie):
   - Wyświetla: "Ładowanie..." (wycentrowane, h-64)
   - Warunek: loading === true && reviews.length === 0

2. PUSTA LISTA:
   - Wyświetla w tabeli: "Brak opinii w systemie."
   - Warunek: reviews.length === 0 (po załadowaniu)

3. NAGŁÓWEK STRONY:
   - Tytuł: "Opinie" (text-3xl font-bold)
   - Podtytuł: "Zarządzaj wszystkimi opiniami w systemie"

4. LICZNIK OPINII:
   - W tytule karty tabeli: "Lista opinii (XXX)"

2.2 STRUKTURA DANYCH OPINII (Interface Review)
--------------------------------------------------------------------------------

interface Review {
  id: string                      // UUID opinii
  ocenaOgolna: number             // 1-5 (wymagane)
  profesjonalizm: number | null   // 1-5 (opcjonalne)
  komunikacja: number | null      // 1-5 (opcjonalne)
  terminowosc: number | null      // 1-5 (opcjonalne)
  stosunekJakosci: number | null  // 1-5 (opcjonalne)
  tytulOpinii: string             // Tytuł opinii
  trescOpinii: string             // Treść (min. 50 znaków)
  polecam: boolean                // Czy klient poleca kancelarię
  anonimowa: boolean              // Czy opinia anonimowa
  zweryfikowana: boolean          // Status weryfikacji
  aktywna: boolean                // Status aktywności
  odpowiedz: string | null        // Odpowiedź kancelarii
  dataOdpowiedzi: string | null   // Data dodania odpowiedzi
  createdAt: string               // Data utworzenia
  updatedAt: string               // Data aktualizacji
  lawFirm: {
    id: string                    // ID kancelarii
    nazwa: string                 // Nazwa kancelarii
    nazwaFirmy: string            // Nazwa firmy
  }
  client: {
    id: string                    // ID klienta
    imie: string                  // Imię klienta
    nazwisko: string              // Nazwisko klienta
    email: string                 // Email klienta
  }
}

interface PaginationData {
  total: number                   // Całkowita liczba opinii
  page: number                    // Bieżąca strona
  limit: number                   // Limit na stronę
  pages: number                   // Całkowita liczba stron
}

AUTORYZACJA:
- Wymaga sesji NextAuth

PARAMETRY QUERY:

┌─────────────────────────────────────────────────────────────────────┐
│ PARAMETR    │ TYP     │ DOMYŚLNIE │ OPIS                            │
├─────────────────────────────────────────────────────────────────────┤
│ page        │ number  │ 1         │ Numer strony                    │
│ limit       │ number  │ 20        │ Liczba rekordów na stronę       │
│ lawFirmId   │ string  │ -         │ Filtr po ID kancelarii          │
│ clientId    │ string  │ -         │ Filtr po ID klienta             │
│ rating      │ string  │ -         │ Filtr po ocenie (1-5)           │
│ verified    │ string  │ -         │ "true" / "false"                │
│ active      │ string  │ -         │ "true" / "false"                │
│ search      │ string  │ -         │ Szukaj w tytule/treści          │
└─────────────────────────────────────────────────────────────────────┘

LOGIKA FILTROWANIA:

1. lawFirmId: where.lawFirmId = lawFirmId
2. clientId: where.clientId = clientId
3. rating: where.ocenaOgolna = parseInt(rating)
4. verified: where.zweryfikowana = (verified === "true")
5. active: where.aktywna = (active === "true")
6. search: where.OR = [
     { tytulOpinii: { contains: search, mode: "insensitive" } },
     { trescOpinii: { contains: search, mode: "insensitive" } }
   ]

SORTOWANIE:
- orderBy: { createdAt: "desc" }
- Najnowsze opinie na górze

PAGINACJA:
- skip: (page - 1) * limit
- take: limit

ZWRACANE RELACJE:

lawFirm: {
  select: {
    id: true,
    nazwa: true,
    nazwaFirmy: true,
  }
}

client: {
  select: {
    id: true,
    imie: true,
    nazwisko: true,
    user: {
      select: {
        email: true,
      }
    }
  }
}

ODPOWIEDŹ (200 OK):

{
  "reviews": Review[],
  "pagination": {
    "total": number,      // Całkowita liczba opinii (po filtrach)
    "page": number,       // Bieżąca strona
    "limit": number,      // Limit na stronę
    "pages": number       // Całkowita liczba stron (Math.ceil(total/limit))
  }
}

BŁĘDY:
- 401: Brak autoryzacji
- 500: Internal server error

5.1 PEŁNA DEFINICJA MODELU
--------------------------------------------------------------------------------

model Review {
  // Identyfikatory
  id                  String   @id @default(uuid())
  lawFirmId           String
  clientId            String

  // Relacje
  lawFirm             LawFirm  @relation(fields: [lawFirmId], references: [id], onDelete: Cascade)
  client              Client   @relation(fields: [clientId], references: [id], onDelete: Cascade)

  // Oceny (1-5 gwiazdek)
  ocenaOgolna         Int      // Wymagana
  profesjonalizm      Int?     // Opcjonalna
  komunikacja         Int?     // Opcjonalna
  terminowosc         Int?     // Opcjonalna
  stosunekJakosci     Int?     // Opcjonalna (stosunek jakości do ceny)

  // Treść opinii
  tytulOpinii         String
  trescOpinii         String   // Minimum 50 znaków (walidowane w API)

  // Opcje
  polecam             Boolean  @default(true)    // Czy klient poleca kancelarię
  anonimowa           Boolean  @default(false)   // Czy opinia anonimowa

  // Odpowiedź kancelarii
  odpowiedz           String?                     // Odpowiedź kancelarii (opcjonalna)
  dataOdpowiedzi      DateTime?                   // Data dodania odpowiedzi

  // Status
  zweryfikowana       Boolean  @default(false)   // Czy opinia zweryfikowana przez admina
  aktywna             Boolean  @default(true)    // Czy opinia aktywna (widoczna)

  // Znaczniki czasowe
  createdAt           DateTime @default(now())
  updatedAt           DateTime @updatedAt

  // Indeksy (prawdopodobnie)
  @@index([lawFirmId])
  @@index([clientId])
  @@index([zweryfikowana])
  @@index([aktywna])
}

5.4 DOMYŚLNE WARTOŚCI
--------------------------------------------------------------------------------

polecam: true
- Domyślnie klient poleca kancelarię
- Można zmienić na false jeśli nie poleca

anonimowa: false
- Domyślnie opinie są jawne (z imieniem i nazwiskiem)
- Klient może wybrać opcję anonimowej

zweryfikowana: false
- Nowe opinie są niezweryfikowane
- Administrator musi ręcznie zweryfikować

aktywna: true
- Nowe opinie są aktywne (widoczne)
- Administrator może dezaktywować niewłaściwe opinie

createdAt: now()
- Automatyczny timestamp tworzenia

updatedAt: automatyczna aktualizacja
- Prisma automatycznie aktualizuje przy każdej zmianie

5.5 WALIDACJA
--------------------------------------------------------------------------------

WALIDACJA W BAZIE:
- Brak dodatkowych constraintów poza typami danych

WALIDACJA W API:

1. ocenaOgolna: 1-5 (wymagane)
2. profesjonalizm, komunikacja, terminowosc, stosunekJakosci: 1-5 lub null
3. trescOpinii: minimum 50 znaków
4. tytulOpinii: wymagany string (nie może być pusty)

WALIDACJA BIZNESOWA:
- Klient może dodać opinię tylko dla kancelarii, z którą miał współpracę
- (to prawdopodobnie walidowane gdzie indziej w systemie)

6. PRZEPŁYW PRACY Z OPINIAMI
================================================================================

--------------------------------------------------------------------------------
6.1 SCENARIUSZ 1: MODERACJA NOWEJ OPINII
--------------------------------------------------------------------------------

1. Klient wystawia opinię w swoim panelu
   ↓
2. Opinia pojawia się w /admin/reviews
   Status: zweryfikowana=false, aktywna=true
   ↓
3. Administrator otwiera /admin/reviews
   - Widzi nową opinię w tabeli
   - Badge "Niezweryfikowana" (szary)
   - Badge "Aktywna" (niebieski)
   ↓
4. Administrator klika "Zobacz szczegóły"
   ↓
5. Administrator przegląda:
   - Treść opinii (czy zgodna z regulaminem)
   - Oceny (czy uzasadnione)
   - Dane klienta (czy prawdziwy użytkownik)
   - Dane kancelarii (której dotyczy)
   ↓
6. DECYZJA ADMINISTRATORA:

   OPCJA A - AKCEPTACJA:
   - Klika przycisk weryfikacji (CheckCircle)
   - Opinia zmienia status: zweryfikowana=true
   - Badge zmienia się na "Zweryfikowana" (niebieski)
   - Opinia pozostaje aktywna i widoczna

   OPCJA B - ODRZUCENIE:
   - Klika przycisk aktywności (XCircle)
   - Opinia zmienia status: aktywna=false
   - Badge zmienia się na "Nieaktywna" (czerwony)
   - Opinia jest ukryta przed użytkownikami

   OPCJA C - USUNIĘCIE:
   - Klika "Usuń"
   - Potwierdza w dialogu
   - Opinia jest trwale usunięta z bazy


--------------------------------------------------------------------------------
6.2 SCENARIUSZ 2: EDYCJA TREŚCI OPINII
--------------------------------------------------------------------------------

1. Administrator zauważa błąd w treści opinii
   (np. wulgaryzmy, błędy ortograficzne, dane wrażliwe)
   ↓
2. Otwiera szczegóły opinii (/admin/reviews/[id])
   ↓
3. Klika "Edytuj"
   - Interfejs przechodzi w tryb edycji
   - Wszystkie pola stają się edytowalne
   ↓
4. Administrator poprawia:
   - Treść opinii (usuwa wulgaryzmy)
   - Tytuł (jeśli potrzeba)
   - Oceny (jeśli były błędnie wystawione)
   - Ustawienia (może zmienić na anonimową)
   ↓
5. Klika "Zapisz"
   - Walidacja: treść min. 50 znaków
   - Jeśli OK: zapisuje zmiany
   - Toast: "Opinia została zaktualizowana"
   ↓
6. Interfejs wraca do trybu przeglądania
   Opinia wyświetla się z poprawkami


--------------------------------------------------------------------------------
6.3 SCENARIUSZ 3: ZARZĄDZANIE ODPOWIEDZIĄ KANCELARII
--------------------------------------------------------------------------------

1. Kancelaria dodaje odpowiedź na opinię w swoim panelu
   ↓
2. Pole "odpowiedz" zostaje wypełnione
   Pole "dataOdpowiedzi" = current timestamp
   ↓
3. Administrator widzi w szczegółach:
   - Sekcja "Odpowiedź kancelarii"
   - Opis: "Odpowiedź dodana: DD.MM.YYYY HH:MM"
   - Treść odpowiedzi kancelarii
   ↓
4. Jeśli odpowiedź jest niewłaściwa:

   OPCJA A - EDYCJA:
   - Administrator klika "Edytuj"
   - Poprawia treść odpowiedzi
   - Zapisuje (dataOdpowiedzi się aktualizuje)

   OPCJA B - USUNIĘCIE:
   - Administrator klika "Edytuj"
   - Czyści pole odpowiedzi (usuwa całą treść)
   - Zapisuje
   - odpowiedz = null, dataOdpowiedzi = null


--------------------------------------------------------------------------------
6.4 SCENARIUSZ 4: WYSZUKIWANIE I FILTROWANIE
--------------------------------------------------------------------------------

1. Administrator otrzymuje zgłoszenie o problematycznej opinii
   Zgłoszenie: "Opinia zawiera słowo 'oszustwo'"
   ↓
2. Otwiera /admin/reviews
   ↓
3. Używa filtrów:
   - Wpisuje "oszustwo" w pole wyszukiwania
   - Opcjonalnie: filtruje po ocenie (np. 1 gwiazdka)
   - Opcjonalnie: filtruje po statusie (aktywne)
   ↓
4. System wyświetla pasujące opinie
   ↓
5. Administrator przegląda znalezione opinie
   ↓
6. Otwiera podejrzane opinie i podejmuje akcje:
   - Edycja treści
   - Dezaktywacja
   - Lub usunięcie


--------------------------------------------------------------------------------
6.5 SCENARIUSZ 5: RAPORTOWANIE OPINII KANCELARII
--------------------------------------------------------------------------------

1. Kancelaria dzwoni: "Proszę pokazać wszystkie moje opinie"
   ↓
2. Administrator otwiera /admin/reviews
   ↓
3. Kopiuje ID kancelarii z innej sekcji panelu
   ↓
4. Dodaje parametr do URL:
   /admin/reviews?lawFirmId=[ID]
   ↓
5. System wyświetla tylko opinie tej kancelarii
   ↓
6. Administrator może:
   - Zobaczyć statystyki (liczba opinii)
   - Przejrzeć średnią ocen
   - Sprawdzić które opinie są zweryfikowane
   - Wyeksportować dane (gdyby była taka funkcja)

7.2 WALIDACJA DANYCH
--------------------------------------------------------------------------------

WALIDACJA PO STRONIE KLIENTA:

1. Minimalna długość treści:
   if (trescOpinii.length < 50) {
     toast.error("Treść opinii musi zawierać minimum 50 znaków")
     return
   }

2. Licznik znaków w czasie rzeczywistym
   Wyświetlany pod Textarea: "{długość} / 50 znaków"

WALIDACJA PO STRONIE SERWERA (API):

1. Wymagane pola (POST):
   if (!lawFirmId || !clientId || !ocenaOgolna || !tytulOpinii || !trescOpinii) {
     return 400 "Missing required fields"
   }

2. Zakres ocen:
   if (ocenaOgolna < 1 || ocenaOgolna > 5) {
     return 400 "Rating must be between 1 and 5"
   }

3. Długość treści:
   if (trescOpinii.length < 50) {
     return 400 "Review content must be at least 50 characters"
   }

4. Istnienie relacji:
   - Sprawdza czy lawFirm istnieje
   - Sprawdza czy client istnieje
   - Jeśli nie: 404 "Law firm or client not found"

5. Istnienie opinii (PUT/DELETE):
   - Sprawdza czy opinia istnieje przed operacją
   - Jeśli nie: 404 "Review not found"

7.3 OBSŁUGA BŁĘDÓW
--------------------------------------------------------------------------------

STRUKTURA TRY-CATCH w API:

try {
  // Logika biznesowa
} catch (error) {
  console.error("Error [opis]:", error)
  return NextResponse.json(
    { error: "Internal server error" },
    { status: 500 }
  )
}

OBSŁUGA BŁĘDÓW W INTERFEJSIE:

1. Błędy API:
   - Wyświetlane przez toast.error()
   - Komunikaty po polsku
   - Szczegółowe opisy błędów

2. Błędy ładowania:
   - Stan loading wyświetla "Ładowanie..."
   - Timeout automatycznie resetuje stan
   - Przy 404: przekierowanie do listy

3. Błędy walidacji:
   - Toast z konkretnym błędem
   - Czerwone obramowanie pól (gdyby używano Form)
   - Zachowanie danych w formularzu (nie resetuje)


--------------------------------------------------------------------------------
7.4 BEZPIECZEŃSTWO DANYCH
--------------------------------------------------------------------------------

OCHRONA DANYCH OSOBOWYCH:

1. Opinie anonimowe:
   - Jeśli anonimowa=true:
     * Nie wyświetla imienia/nazwiska klienta
     * Wyświetla "Anonimowy"
     * Email klienta ukryty w tabeli
   - W szczegółach:
     * Cała karta klienta: "Opinia anonimowa"

2. Soft delete:
   - UWAGA: Review NIE używa soft delete
   - Usunięcie jest TRWAŁE (hard delete)
   - Admin powinien być ostrożny

3. Cascade deletes:
   - Usunięcie kancelarii → usuwa wszystkie jej opinie
   - Usunięcie klienta → usuwa wszystkie jego opinie
   - Automatyczne przez Prisma

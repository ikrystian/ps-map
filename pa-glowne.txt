### 3. SEKCJA WYKRESÓW

Dashboard zawiera dwie karty z wykresami przedstawionymi jako poziome paski
postępu:

---

#### WYKRES 1: SPRAWY WEDŁUG STATUSU
**Tytuł:** "Sprawy według statusu"
**Opis:** "Rozkład statusów spraw"
**Typ wykresu:** Poziome paski postępu z procentami

**Źródło danych:**
```typescript
casesByStatus: await prisma.case.groupBy({
  by: ['status'],
  _count: { id: true }
})
```

**Wyświetlane informacje dla każdego statusu:**
- Nazwa statusu (np. "NOWA", "W_TRAKCIE", "ZAKONCZONA")
- Liczba spraw w tym statusie
- Procentowy udział względem wszystkich spraw
- Pasek postępu (niebieski, bg-blue-600)

**Format wyświetlania:**
```
NOWA                           45 (35%)
███████████████░░░░░░░░░░░░░░░░░

W_TRAKCIE                      60 (47%)
████████████████████░░░░░░░░░░░

ZAKONCZONA                     23 (18%)
████████░░░░░░░░░░░░░░░░░░░░░░░
```

**Obliczenia:**
- Suma wszystkich spraw: total = sum(wszystkie liczności)
- Procent: (liczba_w_statusie / total) * 100
- Szerokość paska: percentage%

---

#### WYKRES 2: PRZYCHODY MIESIĘCZNE
**Tytuł:** "Przychody miesięczne"
**Opis:** "Ostatnie 6 miesięcy"
**Typ wykresu:** Poziome paski postępu z kwotami

**Źródło danych:**
```sql
SELECT
  strftime('%Y-%m', createdAt) as month,
  SUM(kwota) as revenue
FROM "Order"
WHERE statusPlatnosci = 'ZAPLACONE'
  AND createdAt >= [6 miesięcy temu]
GROUP BY strftime('%Y-%m', createdAt)
ORDER BY month ASC
```

**Przetwarzanie danych:**
- Generowane są wszystkie 6 ostatnich miesięcy (nawet jeśli brak danych)
- Brakujące miesiące otrzymują wartość 0
- Format miesiąca: "sty 2025", "lut 2025" (polski format skrócony)

**Wyświetlane informacje dla każdego miesiąca:**
- Nazwa miesiąca (pl-PL format)
- Kwota przychodów (format PLN)
- Pasek postępu względem maksymalnego miesiąca (zielony, bg-green-600)

**Format wyświetlania:**
```
sty 2025                       8 450,00 zł
██████████████████████░░░░░░░░

lut 2025                      12 890,00 zł
████████████████████████████████

mar 2025                       6 230,00 zł
████████████████░░░░░░░░░░░░░░░
```

**Obliczenia:**
- Maksymalna wartość: maxRevenue = max(wszystkie przychody)
- Procent: (przychód_miesiąca / maxRevenue) * 100
- Szerokość paska: percentage%

### 4. WYKRES REJESTRACJI UŻYTKOWNIKÓW

**Tytuł:** "Rejestracje użytkowników"
**Opis:** "Ostatnie 7 dni"
**Typ wykresu:** Słupkowy pionowy (bar chart)

**Źródło danych:**
```sql
SELECT
  DATE(createdAt) as date,
  COUNT(*) as count
FROM "User"
WHERE DATE(createdAt) >= DATE([7 dni temu])
GROUP BY DATE(createdAt)
ORDER BY date ASC
```

**Przetwarzanie danych:**
- Generowane są wszystkie 7 ostatnich dni (nawet jeśli brak rejestracji)
- Brakujące dni otrzymują wartość 0
- Format daty: YYYY-MM-DD

**Wyświetlanie:**
- Wysokość kontenera: 192px (h-48)
- Słupki wyrównane do dołu
- Wysokość słupka proporcjonalna do maksymalnej wartości
- Kolor słupków: niebieski (bg-blue-600)
- Nad słupkiem: liczba rejestracji
- Pod słupkiem: data (obrócona -45°)

**Wizualizacja:**
```
    5      8      3      2      6      4      7
    █      █      █      █      █      █      █
    █      █      █      █      █      █      █
    █      █      █      █      █      █      █
    █      █      ░      ░      █      █      █
    █      █      ░      ░      █      ░      █
  10.11  11.11  12.11  13.11  14.11  15.11  16.11
```

**Obliczenia:**
- Maksymalna wartość: maxCount = max(wszystkie liczności)
- Wysokość słupka: (count / maxCount) * 100%

### FORMATOWANIE DANYCH

Dashboard wykorzystuje następujące funkcje formatujące:

#### 1. FORMAT WALUTY
```typescript
formatCurrency(amount: number): string
```
**Wykorzystanie:** Intl.NumberFormat
- Lokalizacja: 'pl-PL'
- Waluta: 'PLN'
- Format: "12 345,67 zł"

**Przykład:**
```typescript
formatCurrency(12345.67) // "12 345,67 zł"
formatCurrency(1000) // "1 000,00 zł"
```

#### 2. FORMAT DATY
```typescript
formatDate(date: string): string
```
**Wykorzystanie:** Date.toLocaleDateString
- Lokalizacja: 'pl-PL'
- Format: { year: 'numeric', month: 'short', day: 'numeric' }
- Wynik: "10 lis 2025"

**Przykład:**
```typescript
formatDate("2025-11-10T12:00:00") // "10 lis 2025"
```

#### 3. KOLORY STATUSÓW
```typescript
getStatusBadge(status: string): string
```
**Mapa kolorów:**
- ACTIVE: "bg-green-500/10 text-green-500"
- PENDING: "bg-yellow-500/10 text-yellow-500"
- COMPLETED: "bg-blue-500/10 text-blue-500"
- REJECTED: "bg-red-500/10 text-red-500"
- IN_PROGRESS: "bg-purple-500/10 text-purple-500"
- [default]: "bg-gray-500/10 text-gray-500"

### ENDPOINT API - SZCZEGÓŁY

**Endpoint:** GET /api/admin/dashboard/stats
**Plik:** /prosta-sprawa/app/api/admin/dashboard/stats/route.ts
**Autoryzacja:** Wymagana (rola: ADMIN)

#### Struktura odpowiedzi:
```typescript
{
  statistics: {
    totalUsers: number
    totalClients: number
    totalLawFirms: number
    totalCases: number
    totalOrders: number
    totalBlogPosts: number
    totalReviews: number
    activeUsers: number
    pendingCases: number
    unpaidOrders: number
    recentCasesCount: number
    totalRevenue: number
  },
  charts: {
    monthlyRevenue: Array<{ month: string; revenue: number }>
    casesByStatus: Array<{ status: string; count: number }>
    dailyRegistrations: Array<{ date: string; count: number }>
  },
  recentActivity: {
    users: Array<{...}>
    cases: Array<{...}>
    orders: Array<{...}>
    blogPosts: Array<{...}>
  }
}
```

#### Zapytania do bazy danych:

1. **Liczniki podstawowe** (równoległe Promise.all):
   - totalUsers: count wszystkich użytkowników
   - totalClients: count wszystkich klientów
   - totalLawFirms: count wszystkich kancelarii
   - totalCases: count wszystkich spraw
   - totalOrders: count wszystkich zamówień
   - totalBlogPosts: count wszystkich wpisów
   - totalReviews: count wszystkich opinii
   - activeUsers: count użytkowników ze statusem ACTIVE
   - pendingCases: count spraw ze statusem NOWA
   - unpaidOrders: count zamówień ze statusem OCZEKUJE

2. **Przychody miesięczne** (raw SQL):
   ```sql
   SELECT
     strftime('%Y-%m', createdAt) as month,
     SUM(kwota) as revenue
   FROM "Order"
   WHERE statusPlatnosci = 'ZAPLACONE'
     AND createdAt >= [6 miesięcy temu]
   GROUP BY strftime('%Y-%m', createdAt)
   ORDER BY month ASC
   ```

3. **Sprawy wg statusu** (groupBy):
   ```typescript
   prisma.case.groupBy({
     by: ['status'],
     _count: { id: true }
   })
   ```

4. **Rejestracje dzienne** (raw SQL):
   ```sql
   SELECT
     DATE(createdAt) as date,
     COUNT(*) as count
   FROM "User"
   WHERE DATE(createdAt) >= DATE([7 dni temu])
   GROUP BY DATE(createdAt)
   ORDER BY date ASC
   ```

5. **Ostatnie aktywności** (4 zapytania findMany):
   - 5 ostatnich użytkowników
   - 5 ostatnich spraw
   - 5 ostatnich zamówień
   - 5 ostatnich wpisów blog

   }

   ```typescript

     toast.error("Nowe hasło i potwierdzenie nie są identyczne")
     return
   }
   ```

3. **Minimalna długość:**
   ```typescript
   if (newPassword.length < 8) {
     toast.error("Nowe hasło musi mieć minimum 8 znaków")
     return
   }
   ```

---

#### FUNKCJONALNOŚĆ ZMIANY HASŁA

**Proces zmiany hasła:**
```
1. Walidacja front-end (jak powyżej)
   ↓
2. setChangingPassword(true)
   ↓
3. Wywołanie POST /api/admin/profile/change-password
   Body: { currentPassword, newPassword }
   ↓
4. Odpowiedź API:
   - Sukces (200):
     * toast.success("Hasło zostało zmienione")
     * Wyczyść pola formularza
   - Błąd:
     * toast.error(error.message)
   ↓
5. setChangingPassword(false)
```

**Endpoint API: POST /api/admin/profile/change-password**

**Walidacja po stronie API:**

1. **Pola wymagane:**
   ```typescript
   if (!currentPassword || !newPassword) {
     return { error: "Wszystkie pola są wymagane" }, 400
   }
   ```

2. **Minimalna długość:**
   ```typescript
   if (newPassword.length < 8) {
     return { error: "Nowe hasło musi mieć minimum 8 znaków" }, 400
   }
   ```

3. **Weryfikacja użytkownika:**
   ```typescript
   user = findUnique({ where: { id: session.user.id } })
   if (!user || !user.password) {
     return {
       error: "Użytkownik nie znaleziony lub nie ma ustawionego hasła"
     }, 404
   }
   ```

4. **Weryfikacja obecnego hasła:**
   ```typescript
   isPasswordValid = bcrypt.compare(currentPassword, user.password)
   if (!isPasswordValid) {
     return { error: "Obecne hasło jest nieprawidłowe" }, 400
   }
   ```

5. **Aktualizacja hasła:**
   ```typescript
   hashedPassword = bcrypt.hash(newPassword, 10)
   update({
     where: { id: session.user.id },
     data: { password: hashedPassword }
   })
   ```

**Bezpieczeństwo:**
- Hasła hashowane przy użyciu bcrypt
- Salt rounds: 10
- Obecne hasło weryfikowane przed zmianą
- Minimalna długość: 8 znaków

### RÓŻNICE MIĘDZY IMPORTAMI AUTH

**UWAGA WAŻNA:** W kodzie są dwie wersje importu auth:

**W page.tsx (profil):**
```typescript
import { auth } from "@/lib/auth"
```

**W API routes:**
```typescript
import { auth } from "@/auth"  // POPRAWNE według CLAUDE.md
```

**Zgodnie z dokumentacją CLAUDE.md:**
> File: /prosta-sprawa/auth.ts (root level - CURRENT CONFIG)
> Make sure you're importing from root auth.ts
> import { auth } from "@/auth"  // Correct
> NOT from "@/lib/auth"

**Rekomendacja:**
Strona profilu powinna używać `import { auth } from "@/auth"` dla spójności
z pozostałymi częściami aplikacji. Jest to prawdopodobnie nieaktualny import.

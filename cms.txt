1. PRZEGLĄD SYSTEMU CMS
================================================================================

System CMS w Prosta Sprawa to zaawansowany, modularny system do tworzenia
dynamicznych stron internetowych bez potrzeby kodowania. Umożliwia
administratorom:

✓ Tworzenie stron z gotowych modułów HTML
✓ Edycję zawartości przez intuicyjny interfejs
✓ Zarządzanie SEO (meta tagi, opisy)
✓ Publikację/ukrywanie stron
✓ Podgląd stron przed publikacją
✓ Dynamiczne generowanie URL-i (slugi)

KLUCZOWE CECHY:
- Drag & drop reordering modułów
- Dwa typy modułów: TEMPLATE (z polami) i EDITABLE_HTML (czysty HTML)
- System tagów do definiowania edytowalnych pól
- Podgląd na żywo podczas edycji
- Automatyczna walidacja slug'ów
- Cascading deletes - usunięcie strony usuwa powiązane moduły
- Paginacja i wyszukiwanie w panelu admin

2. ARCHITEKTURA I STRUKTURA BAZY DANYCH
================================================================================

MODELE PRISMA:

┌─────────────────────────────────────────────────────────────────────────┐
│ MODEL: Page                                                             │
├─────────────────────────────────────────────────────────────────────────┤
│ id              String   @id @default(uuid())                           │
│ title           String   // Tytuł strony (np. "O nas")                  │
│ slug            String   @unique // URL (np. "o-nas")                   │
│                                                                          │
│ // SEO                                                                   │
│ metaTitle       String?  // Opcjonalny tytuł dla meta tag              │
│ metaDescription String?  // Opcjonalny opis dla meta tag               │
│                                                                          │
│ // Status publikacji                                                     │
│ published       Boolean  @default(false)                                │
│ publishedAt     DateTime?                                               │
│                                                                          │
│ createdAt       DateTime @default(now())                                │
│ updatedAt       DateTime @updatedAt                                     │
│                                                                          │
│ // Relacje                                                               │
│ modules         PageModule[] // Moduły użyte na stronie                │
│                                                                          │
│ @@index([slug])                                                          │
│ @@index([published])                                                     │
└─────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────┐
│ MODEL: Module                                                           │
├─────────────────────────────────────────────────────────────────────────┤
│ id          String     @id @default(uuid())                             │
│ name        String     // Nazwa modułu (np. "Hero Section")             │
│ code        String     // Kod HTML (z tagami lub czysty HTML)           │
│ description String?    // Opcjonalny opis                               │
│ preview     String?    // URL do zdjęcia podglądu                       │
│ type        ModuleType @default(TEMPLATE)                               │
│             // TEMPLATE - z edytowalnymi polami {input-text} itp.      │
│             // EDITABLE_HTML - czysty HTML do edycji WYSIWYG           │
│                                                                          │
│ active      Boolean    @default(true)                                   │
│                                                                          │
│ createdAt   DateTime   @default(now())                                  │
│ updatedAt   DateTime   @updatedAt                                       │
│                                                                          │
│ // Relacje                                                               │
│ pageModules PageModule[]                                                │
│                                                                          │
│ @@index([active])                                                        │
│ @@index([createdAt])                                                     │
│ @@index([type])                                                          │
└─────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────┐
│ MODEL: PageModule (Relacja many-to-many z metadanymi)                  │
├─────────────────────────────────────────────────────────────────────────┤
│ id        String   @id @default(uuid())                                 │
│                                                                          │
│ pageId    String                                                         │
│ page      Page     @relation(fields: [pageId], onDelete: Cascade)      │
│                                                                          │
│ moduleId  String                                                         │
│ module    Module   @relation(fields: [moduleId], onDelete: Cascade)    │
│                                                                          │
│ order     Int      // Kolejność na stronie (0, 1, 2...)                │
│ data      String?  // JSON z wypełnionymi danymi użytkownika           │
│                    // Przykład: {"field_0": "Witamy", "field_1": "..."}│
│                                                                          │
│ createdAt DateTime @default(now())                                      │
│ updatedAt DateTime @updatedAt                                           │
│                                                                          │
│ @@unique([pageId, moduleId, order])                                     │
│ @@index([pageId])                                                        │
│ @@index([moduleId])                                                      │
│ @@index([order])                                                         │
└─────────────────────────────────────────────────────────────────────────┘

RELACJE:
- Page -> PageModule (1:N) - Jedna strona ma wiele instancji modułów
- Module -> PageModule (1:N) - Jeden moduł może być użyty w wielu stronach
- PageModule przechowuje dane specyficzne dla użycia modułu na stronie

CASCADING DELETES:
- Usunięcie Page → usuwa wszystkie PageModule tej strony
- Usunięcie Module → usuwa wszystkie PageModule używające tego modułu

3. TYPY MODUŁÓW
================================================================================

MODUŁ TYPU: TEMPLATE
--------------------
Moduły z predefiniowanymi polami do edycji. Wykorzystują system tagów.

DOSTĘPNE TAGI W KODZIE HTML:
┌─────────────────────────────────────────────────────────────────────────┐
│ Tag                          │ Opis                                     │
├──────────────────────────────┼──────────────────────────────────────────┤
│ {input-text}                 │ Pojedyncze pole tekstowe                 │
│ {textarea}                   │ Wieloliniowe pole tekstowe               │
│ {textarea-wysiwyg}           │ Edytor WYSIWYG (TipTap)                  │
│ {input-email}                │ Pole email (z walidacją)                 │
│ {input-url}                  │ Pole URL (z walidacją)                   │
│ {input-number}               │ Pole numeryczne                          │
│ {select}                     │ Lista rozwijana                          │
│ {checkbox}                   │ Checkbox                                 │
└─────────────────────────────────────────────────────────────────────────┘

SKŁADNIA TAGÓW Z OPCJAMI:
{typ-tagu:opcja1:wartość1,opcja2:wartość2}

PRZYKŁAD:
{input-text:label:Tytuł sekcji,placeholder:Wpisz tytuł}
{textarea:label:Opis,placeholder:Wpisz opis sekcji}
{select:label:Kolor,options:Czerwony|Niebieski|Zielony}

PRZYKŁAD KODU MODUŁU TEMPLATE:
<div class="hero-section bg-gradient-to-r from-blue-500 to-purple-600 py-20">
  <div class="container mx-auto px-4">
    <h1 class="text-4xl font-bold text-white mb-4">
      {input-text:label:Główny tytuł,placeholder:Wpisz tytuł}
    </h1>
    <p class="text-xl text-white/90 mb-8">
      {textarea:label:Podtytuł,placeholder:Wpisz podtytuł}
    </p>
    <div class="prose prose-invert max-w-none">
      {textarea-wysiwyg:label:Treść sekcji}
    </div>
    <a href="{input-url:label:URL przycisku,placeholder:https://...}"
       class="inline-block bg-white text-blue-600 px-6 py-3 rounded-lg">
      {input-text:label:Tekst przycisku,placeholder:Dowiedz się więcej}
    </a>
  </div>
</div>

JAK DZIAŁA PARSOWANIE:
1. System wykrywa tagi w kodzie HTML (regex: /\{([a-zA-Z0-9-_]+)(?::([^}]+))?\}/g)
2. Dla każdego tagu tworzy pole formularza z odpowiednim typem
3. Pola są automatycznie numerowane: field_0, field_1, field_2...
4. Administrator wypełnia pola w interfejsie
5. Dane są zapisywane jako JSON w PageModule.data
6. Podczas renderowania tagi są zastępowane wartościami

PRZYKŁAD DANYCH W PageModule.data:
{
  "field_0": "Witamy w Prosta Sprawa",
  "field_1": "Platforma łącząca klientów z prawnikami",
  "field_2": "<p>Znajdź <strong>najlepszego prawnika</strong> dla siebie</p>",
  "field_3": "https://prostaspraw.pl/szukaj-prawnika",
  "field_4": "Znajdź prawnika"
}

MODUŁ TYPU: EDITABLE_HTML
-------------------------
Moduły z czystym HTML, który może być edytowany bezpośrednio w interfejsie.

CECHY:
✓ Brak tagów - czysty HTML
✓ Edycja przez contentEditable div
✓ Pełna kontrola nad kodem HTML
✓ Możliwość wklejania skomplikowanych struktur
✓ Brak automatycznych pól formularza

PRZYKŁAD KODU MODUŁU EDITABLE_HTML:
<section class="testimonials py-16 bg-gray-50">
  <div class="container mx-auto px-4">
    <h2 class="text-3xl font-bold text-center mb-12">Co mówią nasi klienci</h2>
    <div class="grid md:grid-cols-3 gap-8">
      <div class="bg-white p-6 rounded-lg shadow-md">
        <p class="text-gray-600 italic mb-4">
          "Szybko znalazłem prawnika. Polecam!"
        </p>
        <p class="font-semibold">- Jan Kowalski</p>
      </div>
      <!-- Więcej testimoniali... -->
    </div>
  </div>
</section>

EDYCJA:
Administrator klika w treść i edytuje bezpośrednio w przeglądarce.
Zmiany są zapisywane w PageModule.data jako { "html": "..." }

4. DYNAMICZNE STRONY - /[slug]
================================================================================

LOKALIZACJA: /prosta-sprawa/app/[slug]/page.tsx

DZIAŁANIE:
Każda opublikowana strona jest dostępna pod adresem: /{slug}
Przykłady:
- /o-nas
- /kontakt
- /regulamin
- /polityka-prywatnosci

FLOW RENDEROWANIA STRONY:

1. GENEROWANIE STATYCZNYCH PARAMETRÓW
   ----------------------------------------
   Next.js generuje statyczne ścieżki dla wszystkich opublikowanych stron:

   export async function generateStaticParams() {
     const pages = await prisma.page.findMany({
       where: { published: true },
       select: { slug: true },
     })
     return pages.map((page) => ({ slug: page.slug }))
   }

2. GENEROWANIE METADANYCH SEO
   ----------------------------------------
   export async function generateMetadata({ params }): Promise<Metadata> {
     const { slug } = await params
     const page = await prisma.page.findFirst({
       where: { slug, published: true }
     })

     return {
       title: page.metaTitle || page.title,
       description: page.metaDescription || undefined,
     }
   }

3. POBIERANIE DANYCH STRONY
   ----------------------------------------
   const page = await prisma.page.findFirst({
     where: { slug, published: true },
     include: {
       modules: {
         include: { module: true },
         orderBy: { order: "asc" }
       }
     }
   })

4. RENDEROWANIE MODUŁÓW
   ----------------------------------------
   {page.modules.map((pageModule) => {
     // Parsowanie danych JSON
     const data = JSON.parse(pageModule.data || '{}')

     // Renderowanie w zależności od typu
     let html: string
     if (pageModule.module.type === 'EDITABLE_HTML') {
       // Użyj edytowanego HTML
       html = data.html || pageModule.module.code
     } else {
       // Użyj parsera do zastąpienia tagów
       html = renderModule(pageModule.module.code, data)
     }

     return (
       <div
         key={pageModule.id}
         dangerouslySetInnerHTML={{ __html: html }}
       />
     )
   })}

PRZYKŁAD RENDEROWANEJ STRONY:

URL: /o-nas

STRUKTURA BAZY:
Page {
  slug: "o-nas",
  title: "O nas",
  published: true,
  modules: [
    PageModule {
      order: 0,
      module: { type: "TEMPLATE", code: "<h1>{input-text}</h1>" },
      data: '{"field_0": "Witamy w Prosta Sprawa"}'
    },
    PageModule {
      order: 1,
      module: { type: "EDITABLE_HTML", code: "<p>Tekst...</p>" },
      data: '{"html": "<p>Jesteśmy platformą...</p>"}'
    }
  ]
}

WYRENDEROWANY HTML:
<div class="min-h-screen">
  <div class="page-content">
    <div class="page-module">
      <h1>Witamy w Prosta Sprawa</h1>
    </div>
    <div class="page-module">
      <p>Jesteśmy platformą...</p>
    </div>
  </div>
</div>

OBSŁUGA BŁĘDÓW:
- Jeśli strona nie istnieje → notFound() (404)
- Jeśli strona nieopublikowana → notFound() (404)
- Brak modułów → wyświetla komunikat "Ta strona nie ma jeszcze żadnej zawartości"

WALIDACJA:
- Tytuł: wymagany, min. 1 znak
- Slug: wymagany, tylko małe litery, cyfry i myślniki, unikalny
- Meta tytuł: opcjonalny
- Meta opis: opcjonalny
- Opublikowana: checkbox (domyślnie: false)

AUTOMATYCZNE GENEROWANIE SLUG:
- Podczas wpisywania tytułu, slug jest auto-generowany
- Polskie znaki są transliterowane: ą→a, ć→c, ę→e, ł→l, etc.
- Spacje i znaki specjalne → myślniki
- Przykład: "O nas - Prosta Sprawa" → "o-nas-prosta-sprawa"

────────────────────────────────────────────────────────────────────────────
C. EDYCJA STRONY (/admin/pages/[id])
────────────────────────────────────────────────────────────────────────────

INTERFEJS:
Identyczny jak tworzenie nowej strony, z kilkoma różnicami:

1. Pola są wypełnione danymi istniejącej strony
2. Slug można zmienić (z walidacją unikalności)
3. Moduły są załadowane z PageModule
4. Przycisk: "Zapisz stronę" zamiast "Utwórz stronę"

FLOW EDYCJI:
1. Pobranie danych strony z API
2. Wypełnienie formularza
3. Wypełnienie Page Builder z modułami
4. Edycja przez administratora
5. Zapisanie:
   - Aktualizacja rekordu Page
   - Usunięcie wszystkich PageModule
   - Utworzenie nowych PageModule z aktualną konfiguracją
6. Przekierowanie do /admin/pages

UWAGI:
- Zmiana slug nie powoduje przekierowania starego URL (brak redirectów)
- Jeśli strona jest opublikowana, zmiana jest widoczna od razu

A. PARSEMODULECODE() - Parsowanie kodu modułu
────────────────────────────────────────────────────────────────────────────

FUNKCJA:
export function parseModuleCode(code: string): ParsedModule {
  const fields: ModuleField[] = [];
  const regex = /\{([a-zA-Z0-9-_]+)(?::([^}]+))?\}/g;
  let match;

  while ((match = regex.exec(code)) !== null) {
    const [fullMatch, tagType, options] = match;
    const parsedOptions = parseTagOptions(options);

    // Określenie typu pola
    let fieldType: 'input-text' | 'textarea' | ...

    // Wygenerowanie nazwy pola
    const fieldName = `field_${fields.length}`;

    fields.push({
      type: fieldType,
      name: fieldName,
      label: parsedOptions.label || `Pole ${fields.length + 1}`,
      placeholder: parsedOptions.placeholder,
      options: parsedOptions.options,
      defaultValue: parsedOptions.default
    });
  }

  return { html: code, fields };
}

B. PARSETAGOPTIONS() - Parsowanie opcji tagu
────────────────────────────────────────────────────────────────────────────

FUNKCJA:
function parseTagOptions(optionsString?: string): Record<string, any> {
  if (!optionsString) return {};

  const options: Record<string, any> = {};
  const parts = optionsString.split(',');

  for (const part of parts) {
    const [key, value] = part.split(':');
    if (key && value) {
      if (key === 'options') {
        // Dla select - opcje oddzielone |
        options[key] = value.split('|');
      } else {
        options[key] = value;
      }
    }
  }

  return options;
}

FUNKCJA:
export function renderModule(code: string, data: Record<string, any>): string {
  let rendered = code;
  const regex = /\{([a-zA-Z0-9-_]+)(?::([^}]+))?\}/g;
  let fieldIndex = 0;

  rendered = rendered.replace(regex, (match) => {
    const fieldName = `field_${fieldIndex}`;
    const value = data[fieldName] || '';
    fieldIndex++;
    return value;
  });

  return rendered;
}

D. VALIDATEMODULEDATA() - Walidacja danych modułu
────────────────────────────────────────────────────────────────────────────

FUNKCJA:
export function validateModuleData(
  parsedModule: ParsedModule,
  data: Record<string, any>
): { valid: boolean; errors: string[] } {
  const errors: string[] = [];

  for (const field of parsedModule.fields) {
    const value = data[field.name];

    // Walidacja email
    if (field.type === 'input-email' && value) {
      const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
      if (!emailRegex.test(value)) {
        errors.push(`${field.label}: Nieprawidłowy adres email`);
      }
    }

    // Walidacja URL
    if (field.type === 'input-url' && value) {
      try {
        new URL(value);
      } catch {
        errors.push(`${field.label}: Nieprawidłowy adres URL`);
      }
    }

    // Walidacja number
    if (field.type === 'input-number' && value) {
      if (isNaN(Number(value))) {
        errors.push(`${field.label}: Wartość musi być liczbą`);
      }
    }
  }

  return { valid: errors.length === 0, errors };
}

FLOW TECHNICZNY - ZAPIS DO BAZY
────────────────────────────────────────────────────────────────────────────

POST /api/admin/pages

1. Walidacja sesji (ADMIN only)
   ↓
2. Parsowanie body
   ↓
3. Walidacja:
   - title (wymagany)
   - slug (wymagany, format, unikalność)
   ↓
4. Transakcja Prisma:
   ↓
   4a. Utworzenie Page
       {
         title, slug, metaTitle, metaDescription,
         published, publishedAt: (published ? now : null)
       }
   ↓
   4b. Utworzenie PageModule (dla każdego modułu)
       {
         pageId: page.id,
         moduleId: module.moduleId,
         order: index,
         data: JSON.stringify(module.data)
       }
   ↓
5. Odpowiedź: 201 Created
   ↓
6. Frontend: toast + redirect
